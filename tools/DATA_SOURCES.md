# 词库数据来源、生成与对照审计（v2.9 起）

端侧 `app/src/main/assets/web/data_wubi.js` 是**离线生成**的产物，运行时不产生任何词库外字符串；每个输出词都有真实语料佐证（情境支持）。

## 两类数据

| 数据 | 作用 | 是否提交仓库 |
|---|---|---|
| 单字 / 一~四级简码 | 完全保留五笔86原方案 | 已含（`wubi86_official.dict.yaml`、`wubi86_jidian.dict.yaml`、`gsc_8105.txt`） |
| 词组（2~16字） | 多源真实语料，按五笔取码规则生成、过红线 | 只提交生成产物 `data_wubi.js` |

## 词组的多来源（每个词都有语料佐证）

| 来源 | 文件 | 权重 | 说明 |
|---|---|---|---|
| jieba 高频词 | `modern_words.txt` | 真实词频 | 主力，词频≥10 的纯中文词（约9.4万） |
| 成语 | `xh_idiom.json` | 基础30 | chinese-xinhua，约3.0万（去标点，含长谚语） |
| 歇后语谜底 | `xh_xiehouyu.json` | 基础20 | chinese-xinhua，按分号/逗号拆、限2-6字，约1.6万 |
| 日常口语/俗语 | `daily_spoken.txt` | 基础40 | 手工精选健康口语（X吧/X吗/X呢/应答/祝福），约369条 |

> 外部原始数据（`modern_words.txt`、`xh_*.json`、`blacklist_raw.txt`）因体积与内容原因**不提交本仓库**，请自行获取后放入仓库**上级的构建目录**（与 `gen_wubi_data.js` 同级）：
> - jieba 词典：`fxsjy/jieba`（`dict.txt`）；
> - 成语/歇后语：`pwxcoo/chinese-xinhua`（`data/idiom.json`、`data/xiehouyu.json`）。

## 过滤与红线（离线，全可审计）

1. **手工话题红线 `TOPIC`（子串匹配，因子经精选，约200词，不豁免）**：不涉及国家/政策/政治/宗教/战争/民族/民俗，及黄赌毒、脏话、极端消极词。
2. **第三方违禁大表 `blacklist_raw.txt`（仅整词精确匹配）**：该表假阳性高，子串匹配会误伤"论功行赏、众口交赞、春色满园"等正常成语，故只在"词本身就是敏感词"时生效，不做子串连带。
3. **RAW 假阳性因子自动审计 `FACTOR_ALLOW`**：用 jieba 真实词频反向审计大表——大表中"其本身是高频正常词(≥100)、且不在手工红线"的因子（如人民/社会/公司），自动判为假阳性、不生效。
4. **高频保护**：jieba 词频≥500 的常用词豁免大表误伤。
5. **整词豁免 `ALLOW`**：明确正常的词（国庆、国庆节）。

## 生成命令

```bash
node gen_wubi_data.js
# 端侧按字数：{1:12505,2:54921,3:28639,4:37500,5:2519,6:1046,...,15:2}
```

## 独立对照审计器（用魔法打败魔法）

`audit.js` 是**独立于生成器的第二大脑**，直接审计端侧产物，用独立实现的取码/证据/违规逻辑做三项交叉核对：

| 审计 | 核对内容 | 期望 |
|---|---|---|
| 正向覆盖（加持好魔法） | top2000常用词 + 全部成语 + 口语 + 回归清单，独立算编码后查词库 | 零缺口 |
| 反向违规（打败坏魔法） | 扫描全部输出词，独立红线判定 | 零违规 |
| 情境证据（防乱造） | 每个词是否在真实语料出现 | 零乱造 |

```bash
node audit.js
# v2.9 裁决：PASS（零缺口 / 零违规 / 零乱造），正向覆盖率 98.3%
```

## 用户私有白名单（运行时唯一"新词"来源）

- 用户**主动上屏**的多字词，若静态词库未收、且通过安全预检，才存入本机 `cw_user_words`；
- 精确匹配、不连锁、上限 1000、可一键清空；仅存本机，不上传。

> 边界：只打词组不影响简码与86原方案；零杂质零生造；符合现代汉语规范；不违法、不违背公序良俗；积极阳光向上。
> 原则：宁可漏词，不可违规。
